# パス2「石」— 採点表と調和の門

対象: 石灰岩のファサード、磨き上げられたストラドゥンの舗石、城壁の石積み、石段、
そして「磨いた床」と「粗い壁」の対比。
ベースライン: **`L2`(第1パス採用版)**。反復 `SA`〜`S4` → **`S5`(採用)**。
定点・時刻・seed は第1パスと同一。**`sea.js` / `light.js` / `sky.js` / `main.js` の後段は一行も触っていない。**

## 計器 — `tools/stonestat.mjs`

`harmony.mjs` と同じ分類マスクで画素を要素別に確定し、要素ごとに
**尺度別の局所SD**(r = 1,2,4,8,16,32 px)・**目地の歪度**・**headroom** を出す。

- **r1〜r4** = 石の面そのものの情報(骨材・筆致)。中央値で割った相対値で見る。
- **r16〜r32** = 石ひとつの割りと目地の周期。
- **歪度** = 高周波成分(r=3 の箱平均からの差)の歪み。明るい面を細い暗い線が割れば**負**。
  正なら「明るい目地」= バスルームタイル。
- **headroom** = p99 − 中央値。磨いた床は掠め角で鏡面の帯を持つので大きいはず。

あわせて `tools/_milk.mjs`(**無彩の白** = Y>0.75 かつ彩度<0.06 の割合)を追加した。
第1パスで批評家が問題にしたのは「明るいこと」ではなく「色の無い乳白のベール」で、
明部率だけでは追えなかったため。

## 三人が独立に同じ根に到達した

**(1) 目地が石より高い。** 高さキャンバスの地(= 目地)が石の下限より上にあり、
石の一定割合で目地が「隆起した明るいリッジ」になっていた。

| 生成器 | 地(目地) | 石 | 目地より低い石 |
|---|---|---|---|
| `fortStone` | 136 | 120〜190 | **22.9%** |
| `wornPaving` | 144 | 130〜185 | **25.5%** |
| `stradunPaving` | 153 | 150〜180 | **10.0%** |
| `limestoneWall` | 120 | 168〜220 | 0%(唯一正しい) |

**(2) 低周波の変調が空回り。** ファサードと城壁の「一枚の壁に二色目を置く」唯一の
機構が、変調源に石テクスチャ自身の `.g` を使っていた。sRGB 復号後の実測は
平均 **0.4651 / 0.4406**、SD 0.0837 / 0.0760。式は 0.5 中心を仮定しているので
中心が 0.035 ずれ、**一度も明るくせず常に暗くするだけ**、振幅は ±1.7〜2.3%
= **1 段の 1/14**。4m の石の端から端まで 0.15 段 = 一筆で塗り終わる。

**(3) 床にテクセルが足りない。** 床は画面でいちばんカメラに近い面(足元 1.6m)
なのに、テクセル密度が街でいちばん粗かった(170.7 / 204.8 px/m。ファサードは 320)。
色側の目地は **2px 固定**で、ミップ 1 段で 1px、2 段で消える(= 8〜10m 先で目地が消滅)。
床の高さマップには骨材が**一粒も無かった**(壁は 1 石あたり 61〜184 個)。

## 何を変えたか — すべて石の側

1. **目地は必ず沈む**(`tex.js`)。`fortStone` の地 136→110、`wornPaving` 144→120、
   `stradunPaving` 153→138。石の下限より必ず下に置く。
2. **床のテクセル密度を倍に**(`tex.js`)。`stradunPaving` / `wornPaving` を
   size 1024 → **2048**。タイル周期(coverM)は変えないので反復は増えない。
   目地を実寸から引く(`max(3.4, 0.012·px)` = 12mm / `max(3.2, 0.010·px)` = 10mm)。
3. **床の高さマップに骨材と皿**(`tex.js`)。版の中央を 6〜9mm 窪ませ(700 年の靴)、
   1.2〜4.6mm の粒を撒く。完全な平面鏡は「映るものが動かない鏡」にしかならない。
4. **骨材を「水玉」から「ざらつき」へ**(`tex.js`)。密度 6〜7 倍・振幅を半分に。
   `fortStone` はさらに、石ごとに向きの揃った短い打痕(5〜13mm)7 割 + 等方の粒 3 割。
   法線の強度も落とす(`heightToNormal` 2.8→2.4、`walls.js` の normalScale 1.7→1.35)。
5. **色にも骨材**(`tex.js`)。高さ側 /150 に対し色側 /900 = 6:1 だったので、
   太陽が高い正午は面のアルベドに何も無かった。色側を /60・/70 へ。
6. **低周波の変調を値ノイズ二層に**(`buildings.js` / `walls.js`)。石テクスチャの
   `.g` から `wnNoise` の 68m + 21m(壁は 89m + 27m)へ。振幅 ±18〜19%。
   あわせて色温度も動かす(雨に洗われた面は寒色、庇の下と風下は暖色)。
7. **彩度の低周波**(`tex.js`)。石ごとの色相は ±0.3° に固定したまま、彩度だけを
   石を跨ぐ尺度で 7〜25% に振る(タイル境界で繋がる値ノイズ `lfNoise`)。
8. **磨いた床は摩耗した床より暗い**(`tex.js` / `ground.js`)。HSL 明度 70 → **55**
   (摩耗舗石 58 の下)。拡散の一部が鏡面ローブへ移るのが物理で、鏡面の帯が乗る
   余白もそこで生まれる。目地色も ΔL 27 を保って追随。
9. **磨きが版を跨ぐ**(`tex.js`)。版ごとの放射グラデだけだと磨きの周期が板の周期
   (1.05m)に縛られる。通りの軸に沿った歩行帯(幅 1.1〜2.0m)を roughness に重ねる。
10. **摩耗舗石の市松をやめる**(`tex.js`)。石ごとの明度の振れ ΔL 18(ファサードの 12
    より広い)→ 10。変化の量ではなく**尺度**が間違っていた。失った変化は 6 の低周波へ。
11. **一枚石の見付を作る**(`tex.js` の `dressedFace` + `buildings.js`)。框・戸口枠・
    迫石・巾木・街路の框石は BoxGeometry の面ごとに UV 0..1 なので、幅 0.17m の縦枠に
    3.2m 分の目地が入り、段高 0.26m が **13.8mm の縞**になっていた(= 段ボールの小口)。
    目地の無い細かい肌の専用テクスチャに差し替え。**ドローコールは増えない。**
12. **記念建築の石割りを大きく**(`tex.js` / `monuments.js`)。スポンザ・レクトル館・
    大聖堂を coverM 5.0 / 段高 0.46m の切石に(民家は 3.2 / 0.26m)。
13. **石段に踏面と蹴上の区別**(`ground.js`)。面ごとの頂点色(踏面 1.00 / 蹴上 0.90 /
    下面 0.80)、roughnessMap、そして幅方向の中央ほど磨かれる摩耗と段鼻の丸みを
    シェーダで。**幾何は触っていない。**
14. **ロヴリイェナツの材質を城壁に揃える**(`surround.js`)。`color` も
    `envMapIntensity` も `normalScale` も無く、アルベド 1.0・環境 1.0 だった。
    同じ石灰岩が一枚の絵の中で **0.71 対 0.12 = 2.5 段**に割れ、要塞が日向の積雲より
    明るかった(Y 0.709 > 0.674)。頂点色の 1.04 も 1.0 へ。
15. **家ごとの色相を一点に**(`buildings.js`)。頂点色が 22.1°〜43.6° に散らして
    「街全部が同じ石」を壊していた。**35.3°±2.2°** に固定、彩度の振れも 1/3 に。
    明度の振れ(±0.095)は残す — 街の情報はそこにある。
16. **ルジャ広場を磨いた床に**(`plan.js` / `ground.js`)。広場は 9 頂点の板だったので
    3m ごとに割り、天空可視率の標本を増やした。

## 意図的に触らなかったもの

- **`src/sea.js`(保護)/ `src/light.js` `src/sky.js` `src/main.js` の後段(保護)。**
- **幾何**(家の形・壁の断面・段の数)。石のパスは「面の見え」の話。
- **`ground.js:617` roughness 0.60 / `:619` envMapIntensity 0.62 / 鏡面の丈 3.2** —
  三人とも「壊すな」と書いた第1パスの成果。丈の切り方だけ、**チャンネルごとの min**
  から**比を保った縮小**へ変えた(暖色の太陽で R から順に頭打ちになり、照りが
  色を失って白い舌になるため)。丈は同じ。
- **隅石・歩廊の敷石の向き・巾木の実寸 UV(インスタンス属性が要る)** — 石工の
  所見7・8 の一部。ドローコールを増やさずに入れる余地はあるが、今回の変更量が
  すでに大きいので次の機会に回した。

## 下がったもの(報告)

- **ピレ門内とオノフリオ広場は磨いた床にできなかった。** 実物はストラドゥンの床の
  続きだが、**カメラのすぐ足元が一枚の鏡になる**ため、逆光の朝(`v1_stradun_t1am`)で
  無彩の白が 7.44% → **11.0%** に増え、第1パスの保護値を割った。石の側の手を三つ
  試したが動かなかった(拡散でも直射の鏡面でもなく、掠め角のフレネルによる環境
  鏡面)。磨きを全体で弱めて三枚とも敷くより、いちばん効いた**ルジャ一枚**を残した。
  → ルジャは全時刻で改善(無彩の白 t1am 1.03%→0.58% / t3gold 0.60%→**0.00%**)。
- **`v1_stradun_t2noon` の「色のある明部」が 0.70% → 0.03%。** 磨石のアルベドを
  0.55 まで落としたぶん、正午に白へ届く画素が消えた。正午の磨いた床が沈むのは
  物理として正しい(掠め角でだけ光る)が、数字の上では下がっている。
- **城壁とファサードの平均は動いていない**(相対 r1 で +2%)。近景(`v5_sea` の胸壁、
  `v2_alley` の壁)では 20〜25% 増えているが、遠景ではミップに食われて効かない。
  遠景の石の情報は、テクスチャではなく低周波の変調(6)が担う設計にした。
- **起動が 1.68 秒ぶん重い**(テクスチャ生成)。床を 2048² にした代償。
  ドローコールと三角は不変、実行時の fps は測定誤差の範囲。
