# 第5パス — 空

塗られた大気。雲。水平線へ向かって濃くなる霞。

編集したのは `src/sky.js`(`SKY_RADIANCE_GLSL` / 天蓋シェーダ / 雲 / 星)と
`src/tex.js` の `cloudAtlas` の 1 行だけ。`sunState()` が返す
`zenith` / `horizon` / `horizonFar` / `sunCol` / `fogCol` / `hemiSky` / `hemiGround` /
`sunIntensity` の**値は一つも変えていない**(第1パスの保護対象)。変えたのは、
それらをどう画面に塗るか。

## 計器

`tools/skystat.mjs`(このパスのために作成)。空の画素を仰角 1° の帯で束ね、
**仰角だけの関数として当てはめた縦のグラデーションを最小二乗で引き算する**。
残差 `resid` が空の「絵具」— それが 0 なら、その空は定義上ただのグラデーション
であって、塗られてはいない。人の弁別閾はおよそ 1 L*。

雲は自前の ShaderMaterial(頂点シェーダでビルボード化)なので材質差し替えの
マスクでは 0% になる。**雲を消して撮り直した差**で検出する。

## 見つけたもの(三人の批評家が独立に指した順)

### 1. 雲が太陽の方向を一度も知らない
陰影の唯一の源は `tex.js:647` の `litT = clamp(0.55 + (v - 0.45) * 1.3, 0, 1)` —
**アトラスのセル内の縦座標 v だけの関数**。`CLOUD_VERT` は Y 軸ビルボードなので
テクスチャの上は常にワールドの上。陰影方位は恒久的に真上に固定されていた。
太陽高度 4.7° の黄金時間に、水平な雲頂が受ける放射照度は太陽に正対する鉛直面の
`tan(4.7°) = 0.082` 倍。実在の積雲は「頂は鈍く、太陽側の腹が焼ける」— 12 倍逆さ。

### 2. 雲の暗い側が空より明るい
`sky.js:432` が定数の明るい灰 `(0.42,0.45,0.55)`(Y≈0.447)を重み 0.35 で混ぜ、
さらに `(1 - night*0.8)` の床 0.20 を残していた。天頂がどれだけ暗くなっても
雲底は中明度から下がらない。実測(21:12、太陽 −14°):
**雲の頂 Y 0.1226 / 同じ高さの空 Y 0.0265 / 街灯に照らされた石灰岩 Y 0.0219** —
雲は空の 4.6 倍、石の 5.6 倍明るい。正午でも雲の最暗部(p5 L\*63.6)が同じ帯の
空(p50 L\*62.4)を上回り、**雲のどこにも空より暗い場所が無かった**。

### 3. 雲に時刻が無い
`sky.js:400-409` は `makeSky()` の中で一度だけ回り、`update()` は `sun` を
受け取っているのに角度を回すだけ。個数・大きさ・雲底・方位のどれも時刻を見ない。
`main.js:499` により撮影時 `elapsed` は常に 40 なので、**四時刻の雲は画素単位で同一**。
`M2_v8_luza` の 4 枚すべてで旗竿の左に同じ楕円が同じ画素にいる。
さらに `lit` の輝度は昼のあいだ **常に 4.03 で凍っていた**(`sunCol` は輝度 1 に
正規化済みで、白との lerp も輝度 1 同士)。19:18 の雲(L\*97.4)が正午(L\*92.0)より
明るく、そのとき法線日射は正午の 0.30 倍しかない。

### 4. 雲は 4 個の判子を 14 回押しただけ
`sky.js:406-407` の `(i%2)` / `((i>>1)%2)` は**周期 4**。回転も鏡映も無い。
`tex.js:637` が塊を UV 上で 1.25:1 に潰し、`sky.js:404` の `h = w*(0.42…)` が
スプライトをさらに 0.42〜0.54 倍に潰す — 塊ひとつあたり 2.3:1〜3.0:1。積雲は 1:1。
14 枚すべてが仰角 4.1〜39.5° の一本の環に収まり、路地から見上げるリボンは
四時刻とも雲ゼロ、`v5_sea` では全部が画面上端で切れていた。

### 5. 「塗られた大気」は測ると存在しない
`sky.js:290` の乗算むらは相対 SD 0.96%、`sky.js:292` の加算むらは 2.45%。
合成 2.63% → **ΔL\* 0.68**。`v1_stradun_t2noon` の実測 `resid` 0.757 と一致する。
支配周期は 13°(`d * 4.4`)なので、視野が 12〜18° しかない路地と広場の空の帯では
**その成分がまるごと直流になって消える**。`v8_luza_t2noon` 0.774 /
`v1_stradun_t2noon` 0.757 — 32 行中の最小 2 行、どちらも弁別閾未満。

### 6. 加算のむらが「絶対量」なので、夜に灰色の斑になる
`sky.js:292` の振幅 0.022 はゲイン前の絶対量。空自身のゲイン前輝度は
天頂 0.090(正午)/ 0.011(黄金)/ **0.0007(薄暮)**。同じ 0.022 が
**±12% → ±100% → ±950%** に化ける。`mix(1.0, 0.32, uNight)` では二桁足りない。

### 7. 太陽の暈が直径 27°
`pow(cosθ,140)*5.0`(半値角 5.7°)を加算し、その外を `pow(cosθ,34)*0.55`
(半値角 **11.5°**)が覆っていた。実在の太陽の光冠は 2〜3°。07:54 に画面の
29% を占める空が **日向の石灰岩と同じ明るさ(石/空 1.00)、しかも B/R 1.102 =
ほぼ無彩** の白い穴になっていた。

### 8. 星の密度が仰角で逆転
`sky.js:309` の `d.xz/(d.y+0.35)` は水平線ほどセルを圧縮する。実測
1000deg² あたり **低空 18 個 / 天頂 3 個**。実在(航海薄明、限界等級 4.5)は
約 19 個で、大気減光により低空はその半分以下 — 上下が逆で、天頂が 6 倍足りない。

### 9. 空に方位が無い
方位に依存する項は `mix(uHorizonFar, uHorizon, …)` の 1 本だけで、それは
`horizW = pow(1-h,3.2)` で重み付けされる。正午の `horizon` と `horizonFar` は
輝度がほぼ同じ(0.2302 対 0.2327)なので、この混合は**色は変えるが明るさを
変えない**。位相関数も視線大気量の項も存在しない。仰角 40° と 84° の L\* 差は
**0.3**(弁別閾の 1/3)= 空の上半分が物理的に一枚の色見本。

### 唯一の実質的な後退 — 薄暮の水平線の色相差

| | M2 | P5 |
|---|---|---|
| `v6_lovrijenac_t4dusk` ΔB/R | +0.18 | **−0.11**(符号が反転、大きさ 0.11) |
| `v5_sea_t4dusk` ΔB/R | +0.18 | 0.11 |
| `v7_harbour_t4dusk` 海/空 | 0.75 | 1.02(1.00 を跨ぎ、分離 2%) |
| `v3_roofs_t2noon` ΔB/R | −0.23 | −0.15 |

原因は一つ。**夜の空が正しく暗くなったこと**。M2 の夜空は
(a) 加算のむらが負側で 0 に切り詰められ正側だけがブルームで持ち上がっていたぶんと
(b) 発光する雲 で、実際より 1.4〜1.5 倍明るかった。それが消えた結果、海(街灯と
残照の鏡面で照らされる)が相対的に明るくなり、色相も近づいた。

**海は一画素も動かしていない**(海クラスの最大 Y 変化 1.00%、`v3_roofs_t2noon` の
海 Y 0.3922 / B/R 1.564 は M2 と小数第 4 位まで一致)。動いたのは空だけで、
その空は以前より正しい。ただし**関係としては薄くなった**ので、そのまま記録する。

途中で一度、`skyRadiance` にも水平線の無彩化を入れて **海の B/R を 2.073 → 1.936 に
動かしてしまった**(`v5_sea_t4dusk` ΔB/R が 0.04 まで落ちた)。無彩化と逆転層の蓋は
「観測者から水平線までの長い水平経路」の効果で、反射線に掛けると二重計上になる。
天蓋だけに置き直して海を完全に戻した。位相関数だけは「その方向の空の放射輝度」
そのものの性質なので両方に置いてある。

## 意図して触らなかったもの

- **仰角の基底 `pow(1-h, 3.2)`**。三人のうち二人が「一番はっきり壊れている」と
  指した(仰角 40°→84° で 0.3 L\*)。触らなかった理由は二つ。
  (a) `sky.js:191` の `fogMix` は「遠景が載る仰角 +6°、h=0.10 で horizW = 0.717」を
  前提に `horizon : zenith = 72 : 28` を決めており、これは第1パスの保護値で、
  第4パスの山と島の空気遠近がそこに乗っている。半球平均と h=0.10 の値を同時に
  保存する重みは代数的に存在しない(解くと追加項の係数が 0 になる)。
  (b) **8 つの定点はどれも仰角 0〜30° しか見ていない**(`C*(60)` が全行 `—`)。
  一番壊れている領域が計測に映らない。映らないものを、保護された二つの関係を
  賭けて動かすのは割が合わない。
  代わりに、水平線側(無彩化と逆転層の蓋)と天頂側(位相関数)を別々に入れた。
  基底そのものの作り直しは**次に空を開けるときの最初の項目**。
  旅人が出した三段の重み(`0.30·pow(1-μ,40) + 0.30·pow(1-μ,12) + 0.436·pow(1-μ,1.10)`、
  半球平均 0.2381 を −0.035% で保存)を控えとして残す。

- **`sunState()` の返り値**(第1パスの保護対象)。`sky.js:93` の `violet` が
  定点のどこでも効いていないことは確認したが、そこは直さず、天蓋側に帯として足した。

- **暈の `disc`**(`sky.js:297`)と `mix(600.0, 46.0, uDusk)`。沈む太陽が
  R だけ飽和して赤橙になる仕掛け。

## 積み残し

- 黄金時間の雲被覆は `v7_harbour` で 0.1%。この視点はカメラ高 3.3m・画角 50° で
  画面上端が仰角 +14° しかなく、仰角 7〜45° に散らした積雲がほとんど入らない。
  低い視点から積雲が見えないこと自体は物理的に正しいが、実在の目安 10〜20% には
  届いていない。
- `sunAsym`(同じ仰角での太陽側と反太陽側の L\* 差)は中央値 0.06 → 0.03 で
  ほぼ動いていない。位相関数を `(1−horizW)³` で仰角に立ち上げたので、定点が見る
  仰角 0〜30° では効きが小さい。**空に方位を持たせる仕事は、上の基底の作り直しと
  同時でなければ完成しない。**
- `v4_srd_t3gold` の `sunAsym` は 9.80 → 7.76(−21%)。この視点の方位の非対称は
  `horizonFar`(第1パス、保護)が作っており、そこには触れていない。塗りの分散が
  推定器に乗ったぶんと見ているが、切り分けていない。
- 天の川。太陽高度 −14° では実在でもかろうじて見え始める程度。
- 雲の輪郭が M2 より柔らかい。アトラスのセルが 512² のまま、スプライトが大きく
  なったぶん。
