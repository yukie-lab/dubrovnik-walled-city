# 扉からの入退館

2026-10-05。ユーザーの「扉を押すと入れる」依頼に対応。
既存のカフェと、ルジャ広場のスポンザ館の2か所を対象にした。

## 操作

- C：カフェ前へ。J：スポンザ館前へ。H：操作一覧。
- 入口に近づいて扉をクリック、または正面を向いて F。画面下の案内ボタンでも入れる。
- 木製の両開き扉が開き、短い暗転を挟んで室内へ移動。室内では通常の移動操作で散策する。
- 同じ入口を振り返ってクリック / F で退出。開いた扉を歩いて通ることもできる。
- 昼夜とも利用可能。開いた扉はセッション中そのまま。閉める操作は今回の対象外。
- カフェの左上リンクは復活させない。スポンザ館にも常設の移動リンクは追加しない。

## 空間

カフェは既存の家具・室内を使用。スポンザ館は既存の17×13mの建物に
厚い壁、アーチ開口、床、天井、柱、本棚、帆船模型、地図と羅針盤の展示台、ベンチを追加。
展示室はこのアプリ向けの構成で、現地の間取り・所蔵品を再現したものではない。
外形・屋根・上階・前面の柱廊・家665棟の地理レコードを保持する。

屋外の地形と舗装は建物内だけを切り取り、室内の床を一枚にする。
元の記念建築の台座も外周の石帯に分割し、床の上や入口を横切る板を残さない。
屋外の通行人と街灯が室内に配置されないようにする。展示台・ベンチ・柱・壁・扉には衝突範囲を持たせる。
室内専用の照明と露出の計測をカフェと共有し、スポンザ館は広さに合わせて4灯を使う。
屋外の光源枠と海の設定を変更しない。

## 入力と判定

`entry-door.js` は実体のある左右の扉葉、回転アニメーション、衝突範囲を生成する。
4.5m以内の同じ階から見た実際のアーチだけを選択し、側壁の厚み・柱廊の柱による遮蔽を判定する。
`entry-controls.js` は通常のカーソル、ポインタロック中の画面中央、F キーを共通の判定に接続する。
移動中の連打を無視し、地図・眺め一覧・操作一覧が開いている間は入退館しない。
ショートカットの移動中は扉を選べず、移動直後の入力は更新後の視点で判定する。
別の場所や自動ルートへの移動時は進行中の入退館を取り消す。
入退館先では室内の床の高さを明示し、屋根や別の地面の層に移動しない。

## 検証

```sh
node tools/entry-check.mjs --output docs/entry-check.json
node tools/cafe-check.mjs
node tools/rendercheck.mjs entries-complete --entries --program-audit --program-strict
node tools/rendercheck.mjs entry-outdoor
node tools/refinement-protect.mjs
```

CPU検証は実際の Player と描画三角形を使用し、閉扉の通行止め、開口、床、天井、
室内の家具、壁、歩いての入退館、屋外の通行人の除外を確認する。
ブラウザ検証は扉のクリック・案内ボタン・F キーでの入退館、ポインタロック、連打、
地図を開いた状態・距離外の操作、昼夕夜の室内、通常プレイの露出と退出後の復帰を確認する。

結果：両室の入退館・閉扉の通行止めに合格。入口通路14点と室内の通行可能な床44点で、
足元と描画された床が一致した。室内の18視点は全て安定し、描画158〜182回、GPUエラー0。
104材質のプログラムに衝突・欠落なし。通常プレイでは80フレームにわたって室内の露出順応を維持し、
退出後に屋外の照度計へ復帰した。海・大通り・路地・屋根の4視点も安定し、描画142〜185回。
これは表示安定性の確認であり、変更前との完全な画素一致の検証ではない。
665棟、城壁、街路、既存ルート・眺めの定点、保護ソースの検査も合格した。
