# 最初の入れる建物 — KAVANA

2026-10-03。ユーザーの依頼により精錬キャンペーンを pass 46 で終了し、
新機能としてストラドゥン北側の既存の1棟に、歩いて出入りできるカフェを追加。

## 使い方

- 左上の「カフェ前へ」または C キーで入口前へ。現在の時刻は保持。
- 開いた石のアーチを W キーで通り、店内を歩く。同じ入口から外へ戻れる。
- 昼夜とも入れる。店内での追加アクションや扉の開閉操作はない。
- 手描き地図、眺めへの移動、自動ウォークは引き続き利用可能。

既定 seed の対象は中心 X=-86.680105、Z=-8.125、外寸 6.008×7.35m の家。
入口は X=-86.680105、Z=-4.45。新しい建物を増やさず、既存の1階だけを使用。
別 seed では同じ北側の範囲から条件に合う家を選ぶ。

## 実装

`cafe-layout.js` が床、壁厚、アーチ開口、家具の通行範囲を定義。
`buildings.js` は対象1棟の下階を厚い壁で囲い、対応する店舗の閉じた扉と
見せかけの室内平面を外す。屋根・外形寸法・上階はそのまま。
`cafe.js` は建物直下の地形だけを切り取り、石床・天井・内壁・梁・カウンター・
テーブル・椅子・食器・照明・看板を生成する。屋外の入口を塞ぐ鉢植えは除外。

`plan.js` は室内の床と壁・家具の衝突範囲を使う。プレイヤーの移動操作は共通で、
別シーンへの切り替えや入退店時のテレポートは行わない。

室内材質だけに有限の2灯を適用し、屋外の点光源スロットは8灯のまま。
入口からの奥行きに応じて室内の採光と照度計を変え、既存の時間的な露出順応を使用。
出ると室内の照度計を解除する。室内では波音を弱め、石床の足音に短い残響を加える。
実スピーカーによる試聴は対象外。

海のソースと光学設定、家665棟の地理レコード、城壁・街路・既存経路・プリセットを保持。
`plan.js` の変更はユーザーが依頼した室内床・衝突解決の例外として保護検査に明記し、
旧ベースラインのハッシュは書き換えない。

## 検証

```sh
node tools/cafe-check.mjs --output docs/cafe-check.json
node tools/rendercheck.mjs cafe-final --cafe --program-audit --program-strict
node tools/refinement-protect.mjs
```

CPU 検査は実際の Player を使った入退店・壁・カウンター・テーブル・斜め移動と、
描画三角形へのレイによる床・天井・壁・開口を確認する。
ブラウザ検査は実キー入力、ボタンと C キー、昼・夕方・夜の入口／室内／出口、
通常プレイ時の露出順応と屋外状態への復帰を確認する。

結果: CPU の8項目は合格。昼・夕方・夜×3視点の9枚は静止画像が安定し、
描画151〜158回、GPU エラー0。87材質の検査でプログラム衝突・欠落0。
通常プレイの100フレームで室内状態と有限の露出を維持し、露出は103.69から
97.11へ目標96.21に向かって順応。退出時に `stradun` と屋外の照度計へ復帰。
看板に影を受けさせる最終修正後も、正午の室内を再撮影して安定を確認。

海・大通り・路地・屋根の4視点も描画138〜170回、静止画像と画面合成が一致。
これは表示の安定性の検査であり、変更前との完全な画素一致は主張しない。
既存の4自動ルート、6階段、北路地15本と外周往復の歩行検査も合格。
海など4保護ソースと、665棟・城壁・街路・経路・プリセットの保護検査も合格。
既定値と3種類の追加 seed で対象建物の選択とレコードの JSON 化を確認した。

結果は `docs/cafe-check.json` と `docs/cafe-rendercheck.json`。
画像は `shots/rendercheck/cafe-final-*`、最終の正午室内は
`shots/rendercheck/cafe-sign-cafe-0-direct.png`。

今回の機能は1階の散策まで。2階、扉の開閉、着席、注文、店員との会話は未実装。
室内の2灯は室内材質に対する拡散照明で、家具による個別の局所光の影は未実装。
