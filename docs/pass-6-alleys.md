# 第6パス — 体験としての路地

日陰へ入る瞬間の明暗差、狭さ、空のリボン、生活の痕跡。キャンペーン最後の要素。

編集したのは `src/plan.js`(家の列の詰め方)、`src/buildings.js`(開口の着地・縦樋・
壁の第三層と上り湿気)、`src/life.js`(洗濯紐と街灯の配置)。
第1〜5パスの保護値には触れていない。

## 計器 — まず自分の四つの誤りを直した

第1パスで `lightprobe` が IBL を数えていなかったのと同じ種類の誤りを、
このパスの準備で**四つ**作った。三人の批評家が全部捕まえた。

| 誤り | 実際 |
|---|---|
| 「洗濯物が軒の高さに干してある」 | 絶対高 18.2m を **別の場所**(z=−22、床 6.79m)の床と比べていた。その 12 枚は z=−50.8/−55.2 にあり、床は 13.82m。床上 **4.37〜4.49m**。全市 568 枚の中央値 **4.40m** で実在の 3〜7m の中。`life.js:75` は正しい |
| 「路地の半分が街路の露出で描かれている」 | `alleylight.mjs` が代表点を**幾何中央 1 点**に取っていた。72.5m の北路地の中央 z=−37.75 はプリイェコ(半幅 2.10m)の**中**。交差点を外した 139 点では **139/139 が alley**。天空率の中央値も 0.261 ではなく **0.155** |
| 「日陰へ入る瞬間の明暗差が小さい」 | 画面中央値で測っていた。ストラドゥンに立った時点で画面の大半は既に路地の壁。**足元の床(画面下 10%)**で測ると 07:54 に Y 0.1725 → 0.0159 = **10.8:1 = 3.44 段**。第1パスの光の模型は正しく、露出は追っていない |
| 空のリボンの角度 | `2·atan((w/2)/h)` を**床から・bbox 内の最高軒**で計算していて系統的に過小。目線 1.6m から実際に抜けた角度で測ると 17.8°(旅人の 91 方向断面では 22°) |

さらに実装中に **`varying float vUp;` を二重に宣言**して GLSL のコンパイルを壊し、
マテリアルが代替に落ちて石が街じゅうで 23〜35% 暗くなった。門の値を二度変えても
ビット単位で同じ結果が出たことで気づいた。**変更が本当に効いているかを測れ。**

## 見つけたもの

### 1. 路地の立面 278m が、厚 0.5m・高さ最大 10.83m の目の無い板

`plan.js` の家の列は `x0` から左詰めで埋め、`while (x < x1 - 3.2)` と
`if (wReal < 3.0) break;` で終わる。**余り(0〜3.2m)は街区の構造上、必ず列の
+x 端 = 次の路地の西側に落ちる。** そこが未建築のまま残り、庭塀の補完が
`w: 0.5` の板でそれを塞ぐ。`garden: true` は `buildings.js:916` の
`if (h.garden) continue;` により**窓・扉・縦樋・巾木・軒・屋根をすべて失う**。

実測: 厚 0.9m 未満の板 **40 枚 / 総延長 278m**、うち高さ 3.5m 超が 24 枚、
最大 **10.83m**(意図は 2.3m の塀)。北の路地の西壁が東壁より系統的に貧しい
(扉 4 対 8、縦樋 0 対 7、街灯が全部東側)のは、この一箇所が原因。

### 2. 戸口が段に着地していない

`f.groundY` は面の中点 1 点で測ったスカラー。路地は勾配 25% で登るので、
面長 8.5m では 2.1m の落差を 1 つの高さで代表している。巾木は石一枚ごとに
`plan.groundAt` で測り直しているのに、扉だけがそれをしていない。
実測(路地の戸口): 敷居 − 足元の地面 = **p25 −0.132m / 中央 +0.251 / p75 +0.425 /
最小 −0.289 / 最大 +0.664**。四分の一が舗装に埋まり、四分の一が宙に浮く。

### 3. 路地面に縦樋が一本も立たない

`buildings.js:970` `if (!isAlleyFace(f) && !h.monument)` が**路地面を明示的に除外**。
実物では雨は必ず路地へ落とす。切石の無地の壁に律を与える唯一の垂直線。

### 4. 腕の届く壁に絵具が一度も置かれていない

一枚の壁に二色目を置く唯一の機構(`buildings.js:462`)の周期は **68m と 21m**。
**腕の届く壁が張るのは 3m なので、そこではどちらも直流になって消える。**
第5パスが空で見つけたのと同じ故障(支配周期 13° は視野 12〜18° の路地の帯では
直流になる)。実測の局所 SD 8px は日陰の三時刻で **0.53〜0.61 L\***(弁別閾未満)、
直射のある正午だけ 2.03 — いまの肌理は法線マップ頼りで、
**「太陽が床を照らして跳ね返る時だけ」現れる光依存の肌理**だった。

### 5. 洗濯紐と街灯の分布

洗濯紐は `life.js:64` が一様乱数で位置を振るので、拒否条件を通った紐が偏る。
実測 alleyN2 の 72.5m に **2 本だけ**、しかも z=−50.8 と −55.3 の 4.4m 間隔で
奥に密集し、手前 45m はゼロ。街灯は `s2.pts[1]` を終点にしていたので**折れ線の
第一区間しか見ず**、`gap = 15` は実測 18m に 1 基(実在は 8〜12m)、
高さは **46 基すべてが床上ぴったり 3.20m**、壁座は設計幅で置くので壁から 0.19m 浮く。

## 判断を上げる — 路地の狭さ

**空のリボンは 18.1°(旅人の 91 方向断面では 22°)。実在は 7〜11°。**

このパスで幅は 2.85 → 2.55m、h:w は 3.59 → 4.32 まで来たが、リボンの角度は動かなかった。
壁高が 10.3m しかないため。実在の Žudioska / Zlatarska は **4〜5 層 = 14〜16m**。

三人の批評家が別々に同じ結論に達している:

- 建築史家 — 北帯を `fl: [2,3]` → `[3,4]`、`eaves = max(eaves, yTop + 2.5)` → `yTop + 6.2`
- 旅人 — 「上の四つを全部やっても 16° 止まり。9〜11° には北の帯を 1 層上げる以外に道がない。
  それは第3パスの屋根の海(ミンチェタからの眺め)を動かすので、**このパスの権限では決められない**」
- 画家 — 設計幅を 2.18 → 1.9m にすれば h:w 5.4・空 10.7° で実在に入るが、通行判定と
  `life` の配置に影響する

**北の家並みに 1 層足すと、第3パスで確定した屋根の海の高さと、第4パスの
「歩廊からスルジと海が見える」視線が動きます。** キャンペーンの規約により、
先行パスを動かす判断は私では決められないので、報告します。

## 積み残し

- 手前 4m の壁に「手の届く高さの物」を足す(郵便受け・番地札・水道元栓の箱・
  洗濯紐の腕木・持ち送り・猫の餌皿)。批評家の推薦は**新規 InstancedMesh 2〜3 本**で、
  余裕 14 本の中に収まる。
- 段の履歴。踏面と蹴上の寸法は実在どおり(蹴上 0.145〜0.186m / 踏面 0.58m)だが、
  122 段すべてで摩耗が画素単位に同一。段鼻の面取りと踏面中央の 15mm の窪みは
  既存の `steps` InstancedMesh に入る。
- `interpenetration house.plinth|steps` 1884 件。巾木を踏面ごとに切る。
- 影のブロック状の縁。路地が正しく囲われたぶん影が増えて目立つが、
  `radius = lerp(40, 170, upK)` は第1パスの保護値。
- 鉢を窓台と腕木にも置く(現状は全部が床置き)。
- 「日陰へ入る瞬間」の**過渡**を撮る計器。`main.js:530` の `lighting.state.snap = SHOT`
  により τ が 0.0001 になるので、**このキャンペーンの 1 枚も順応の途中を写していない**。
  `glare` は全撮影で恒等的に 0。定常の落差(3.44 段)は正しいと確認できたが、
  過渡は採点表に一行も無い。
